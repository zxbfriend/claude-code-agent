# 工作流：Bug 修复（Bug Fix）

> 链路短，精准派发，不需要 architect-agent。

---

## 触发条件

用户输入包含：Bug、错误、报错、不对、异常、崩溃、显示错误 等关键词时，走本流程。

---

## 完整流程

```
Bug 报告
   │
   ▼
Step 1: pm-agent
   ├── 分析 Bug 现象，归属判断：
   │     ├── 页面显示错误 / UI 问题 → frontend-agent
   │     ├── 接口返回数据错误 → backend-agent
   │     ├── 数据库数据不一致 → dba-agent + backend-agent
   │     ├── 前端计算结果≠后端 → 需同时排查前后端
   │     └── 多端都有 / 接口契约问题 → 可能需要 architect-agent
   ├── 生成 Bug 单（包含：复现步骤、预期/实际结果、归属、优先级）
   └── → 派发给对应 Agent

Step 2: [对应 Agent] backend-agent / frontend-agent / dba-agent
   ├── 复现 Bug
   ├── 定位根因
   ├── 实施修复
   └── 输出：修复代码 + 修复说明

Step 3: qa-agent
   ├── 验证修复是否有效（执行原 Bug 复现步骤）
   ├── 定向回归：测试受影响的相关功能（不做全量回归）
   ├── 如修复无效 → 通知对应 Agent 重新排查
   └── 输出：验证报告（Verify Fix）

Step 4: reviewer-agent
   ├── 检查修复方案是否引入了新问题
   ├── 验证修复的影响范围是否可控
   └── 输出：Review 结论
```

---

## Bug 单格式

```markdown
## Bug 单

**Bug ID**：BUG-{YYYYMMDD}-{序号}
**关联任务**：{TASK-ID}（如有）
**严重级别**：Critical / High / Medium / Low
**归属 Agent**：backend-agent / frontend-agent / dba-agent
**优先级**：P0（阻塞）/ P1（本迭代）/ P2（排期）

### 问题描述
{用一句话描述问题}

### 复现步骤
1. {步骤1}
2. {步骤2}
3. {步骤3}

### 预期结果
{应该是什么}

### 实际结果
{实际是什么}

### 环境信息
- 版本：v{X.X.X}
- 环境：dev / staging / prod
- 浏览器/端（如前端问题）：{信息}

### 附件
{截图、日志、请求/响应内容}
```

---

## 关键约束

```
1. 【不调用】architect-agent（除非 Bug 是架构设计问题）
2. 【不调用】不相关的 Agent（pm-agent 精准归属后才派发）
3. qa-agent 只做定向回归，不做全量测试
4. 如同一 Bug 反复出现，pm-agent 需要考虑是否升级为"技术重构"任务
```

---

## Bug 严重级别定义

| 级别 | 定义 | 示例 |
|------|------|------|
| Critical | 核心功能完全不可用，影响所有用户 | 登录接口 500，所有人无法登录 |
| High | 重要功能异常，影响大量用户 | 支付金额计算错误 |
| Medium | 功能部分异常，有临时解决方案 | 列表排序不对，刷新可临时解决 |
| Low | 展示问题、文案错误，不影响主流程 | 按钮文字错误，图标位置偏移 |

---

## 异常处理

| 异常情况 | 处理方式 |
|---------|---------|
| 修复后 qa-agent 验证仍失败 | 退回对应 Agent 重新排查 |
| Bug 根因在接口设计层面 | 升级为需求变更，评估是否需要 architect-agent |
| 修复影响范围超预期 | 通知 pm-agent 重新评估，可能升级为新功能开发流程 |
