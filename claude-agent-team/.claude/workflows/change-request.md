# 工作流：需求变更（Change Request）

> pm-agent 的影响范围判断至关重要，决定走哪条路。

---

## 触发条件

用户输入包含：变更、调整、修改需求、需求有变 等关键词时，走本流程。

---

## 完整流程

```
变更请求
   │
   ▼
Step 1: pm-agent（关键：影响范围分析）
   ├── 分析变更涉及的范围：
   │     ├── 仅前端（UI/样式/文案）？
   │     ├── 仅后端逻辑（接口不变）？
   │     ├── 接口有变动？
   │     └── 需要新增/修改数据库表？
   │
   ├── 影响范围判断 → 路由决策：
   │     ├── 小变更（仅 UI/文案/样式，无接口变动）
   │     │     → 走 Bug 修复流程（bug-fix.md）
   │     │
   │     ├── 中变更（逻辑调整，接口字段增减但不破坏兼容性）
   │     │     → 跳过 architect-agent，直接派发开发 Agent
   │     │
   │     └── 大变更（接口变动/新增接口/DB 变更）
   │           → 走新功能开发流程（new-feature.md）
   │
   └── 输出：影响分析报告 + 路由决策
```

---

## 影响分析报告模板

```markdown
## 需求变更影响分析

**变更描述**：{变更内容}
**分析结论**：小变更 / 中变更 / 大变更

### 影响范围
| 层面 | 是否受影响 | 说明 |
|------|-----------|------|
| 前端 UI | 是/否 | {说明} |
| 后端逻辑 | 是/否 | {说明} |
| 接口定义 | 是/否 | {变更接口列表} |
| 数据库 | 是/否 | {变更表/字段} |

### 路由决策
走：**Bug 修复流程 / 中变更直接开发 / 新功能开发流程**

### 原因说明
{说明为什么做出此判断}
```
